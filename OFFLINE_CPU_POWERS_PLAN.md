# Offline CPU seats draw and use powers at a Wild table (STO-505)

## Context

At an offline Wild table (`/offline?powers=wild`), only the hero draws and holds a power: `startHand` is passed `powerUps: { deal: "choose3", bots: BOT_IDS }` so the engine leaves the CPU seats out of the Power Draw. `decideOfflineMove` handles betting (and returns `deal` at payout); it never picks or uses a power. [STO-505](https://linear.app/magnus-adhd-brain/issue/STO-505/offline-cpu-seats-draw-and-use-powers-at-a-wild-table) asks for every CPU seat dealt in to get an offer and pick one, and to be able to use what it holds — same engine legality as the hero (`canUsePower`), same public seams (nameplate tag, "power used" card), each CPU action its own `duration.cpuBeat` commit, the draw still holding the table, and Classic tables unchanged. A bot's held power, offers and swapped letter stay private until the rules make them public: the use reveals its power, and a swapped tile played at showdown reveals its letter with the ⚡ marker. Test the policy's information access and every public projection; checking only the hero's rack is insufficient.

Existing seams: `powerUsedBy` and `noteSeatAction` in `use-offline-game.ts` already accept any seat's `usePowerUp`; `PowerUsedCard` prints `<NAME> USED` for other seats and queues notices; the showdown marker uses `isSwappedTileId(tile.id)`, independently of the seat. `PowerDrawReveal` already supports a hero pick while other seats are still choosing. Reuse these components and add coverage of their offline integration. No new UI component or wire contract is planned.

This document plans the implementation; it does not claim the new behavior has been run. Before writing Expo code, read the exact SDK 57 docs at https://docs.expo.dev/versions/v57.0.0/ and follow `docs/CODE_STYLE.md`. Review the changed timer effect with the `use-effect-killer` skill as that guide requires. Source anchors below describe the current code; locate the named functions and tests rather than relying on line numbers after edits.

### 2. Bot policy: `packages/game-rules/src/bot/bot-power.ts` (new file, next to bot-policy/bot-word)

No power policy exists today. Add two pure functions. Strategic evaluation sees only `observeBot` (bot-observation.ts); structural lookup reads the acting seat, its own draw slot and held power, and engine legality. Never read another seat's offers, held swap, rack, draft, word checks, or the future board. Both rolls use `botDecisionSeed(view, purpose)`. The use policy receives time as an argument solely for legality; it never reads a clock or includes time in its random seed.

```ts
/** §44's Power Draw, as a CPU seat picks it: rack fit and personality, never another seat's tiles. */
export function chooseBotPower(state: OfflineState, botId: PlayerId): PowerUpId;
/** Whether a CPU seat spends a legal held power at the supplied time, on its own private tile. */
export function decideBotPowerUse(
  state: OfflineState,
  botId: PlayerId,
  nowMs: number,
): { powerUpId: PowerUpId; tileId: string } | null;
```

`chooseBotPower`: find the seat's slot in `state.powers.draw.slots` (throw `OfflineActionError` if the draw isn't open, the seat has no slot, the slot is already picked, or it has no offers). Use `slot.seat` for the observation: `view = observeBot(state, slot.seat, state.betting ?? { currentBet: 0, lastRaiseSize: 0 })`. The adapter checks the draw deadline before calling this policy; `reduce` still enforces the actual pick deadline. Weight only the slot's offers and roll once with `createRng(botDecisionSeed(view, "power-pick"))`, cumulative weighted pick in offer order:

- `vowel_magnet`: rack tile "has a vowel" = any face of the tile (`alternativeLetter` included) is in AEIOU. No vowel tile → **4**, exactly one → **2**, else **1**.
- `mulligan`: `evaluateBestWord({ available: view.privateTiles, dictionary: view.dictionary }) === null` (the rack alone spells nothing) → **2**, else **1**. At the draw the board is unrevealed (`observeBot` slices to `revealed` = 0 preflop), so rack-only is all it can see — by design.
- `random_wild`: **0.5 + botProfile(seat).aggression** (cautious 1.05, tricky 1.2, aggressive 1.4).

`decideBotPowerUse` first returns `null` when `canUsePower(state, botId, nowMs)` is false. Do not copy the engine's structural activation checks into the policy: this gate covers the draw, held/used/folded state, own turn, unconfirmed word slot, and deadline. Re-read and validate the seat and its held power without casts or non-null assertions, then build the observation (word-window calls pass the zero round because betting is null there). If there are no private tiles, return `null` rather than naming an undefined target.

- `best = evaluateBestWord({ available: [...view.privateTiles, ...view.board], dictionary: view.dictionary })`; form used IDs from `best?.submission.plays ?? []`. `dead` = the seat's private tiles whose IDs are absent from that set, sorted by ID ascending; `target = dead[0]`, else the lowest-`points` private tile (tie: ID ascending). Sort copies, never the input rack. When `best` is null every private tile is a dead-tile candidate.
- `tier = assessBotStrength(view).tier`; probability `p = base[tier] × style.curiosity`, `base = { weak: 0.7, playable: 0.5, strong: 0.3, premium: 0.15 }`, ×1.3 when the target is a dead tile, ×1.3 inside §19's window (last chance), capped at 0.95. A dead-tile swap preserves the currently selected best word, but can surrender future flexibility; the no-dead-tile fallback can weaken the current word. This is a personality heuristic, not a guaranteed improvement.
- `createRng(botDecisionSeed(view, "power-use"))() < p` → `{ powerUpId: held.id, tileId: target.id }`, else `null`.

Export both from `packages/game-rules/src/index.ts` (`export { chooseBotPower, decideBotPowerUse } from "./bot/bot-power";`) — the adapter imports from `@wordpoker/game-rules`.

### 3. Adapter: schedule the picks and uses (use-offline-game.ts)

- `openTable`: pass only `powerUps: { deal: "choose3" }` and delete `BOT_IDS` and its obsolete comment.
- Change `nextCpuMove` to accept an injected `nowMs`. Return null at payout or once the current draw/word/turn deadline has passed; the existing deadline timers own settlement. Its three branches are:
  1. **Draw open**, before the word-window branch: require the hero's own slot to have a non-null pick. Find the first unpicked non-hero slot in seat order and return its `pickPower` using `chooseBotPower`. Do not use a missing hero slot as permission to pick. The timeout closes the draw and assigns first offers to unpicked seats without CPU pick beats.
  2. **Word window**: for each non-hero drafting slot, consider `decideBotPowerUse(state, slot.playerId, nowMs)` before `chooseOfflineWord`. Return a use as the whole action for this beat. Recompute the submission from the updated rack on a later beat. If neither a use nor a word exists, continue to later slots; leave that seat to the window's clock.
  3. **Betting turn**: before `decideOfflineMove`, consider `decideBotPowerUse(state, acting.id, nowMs)`. The use is its own beat and preserves commitments, round, actor and deadline. The next beat recomputes the bet from the swapped rack. Its seeded random rolls retain the betting context, but its strength and resulting betting action can change.
- **Beat effect dependencies**: add `state.powers`. An intermediate `pickPower` changes only powers, so this is required to schedule the remaining picks. Preserve cleanup and all existing dependencies.
- Avoid evaluating the new word-search policy eagerly just to arm a timer: replace the effect's `nextCpuMove(state) === null` preflight with a cheap local scheduling predicate. It checks only whether an unexpired table has a picked hero plus an unpicked bot draw slot, any bot drafting slot, or a bot betting actor. It does not choose an action or decide legality. Compute `nextCpuMove(current, Date.now())` only inside the beat callback against `stateRef.current`. If it returns null, make no commit; a wordless window does not poll repeatedly without a state change.
- Keep the existing one-beat word-window guard. Re-read time after synchronous policy evaluation; if the deadline passed while searching, drop the move and let its timer settle the table. For a use, recheck `canUsePower` at that commit time and pass the same time to `act(move, nowMs)`/`reduce`. Thus the policy respects its supplied time and the adapter also handles elapsed computation. Retain `act`'s rejection handling for stale inputs, not as the policy's legality mechanism.
- A use does not reset or extend the turn clock. Do not reserve two beats by silently renewing it; a use near the deadline can legitimately leave too little time for the following bet/confirm. Verify this edge explicitly.

Reuse `powerUsedBy`, `noteSeatAction`, `powerViewOf` and `perspectiveOf` without exposing bot-private state. The hero's `pickPower`/`usePower` dispatch paths stay as they are. No CPU use or betting beat waits for a public card to clear; the card queue is a presentation timer, while the engine's activation deadlines continue running.

### 6. Docs

- `docs/rules/power-ups.md` § Offline Play — every seat dealt in at an offline Wild table draws, including all-in seats; sitting-out seats do not. The hero picks by hand. CPU pick policy sees its own rack and personality (the board is unrevealed during the draw); CPU use policy also sees the revealed board and public betting context. No CPU policy action runs while the hero is unpicked and the draw is open. After the hero picks, CPU seats pick in seat order, one per beat. The shared 10-second clock still closes the draw and assigns first offers to all unpicked seats, including an unpicked hero; this timeout assignment is an engine settlement, not a batch of policy actions. Nobody bets or starts a betting turn clock until the draw closes. CPU seats may use a held power on their own live betting turn before acting, or in §19's live window before confirming, with the same public card/tag and private result. Each CPU pick, use, bet and confirm is a separate beat; using a power never renews the clock.
- `docs/rules/hand-flow.md` §13 "Offline CPU play styles": add one paragraph after the decision-order paragraph, in the section's voice: CPU seats draw and hold like the player (§44); a rack with no vowel face favors Vowel Magnet, a rack that spells nothing alone favors Mulligan, and the roll is seeded like every other decision. A seat is more likely to spend its power when its hand needs it — its own turn before it acts, or §19's window before it confirms. It prefers discarding a tile outside its best current word, otherwise its lowest printed-value private tile; using a power is one beat, then the seat plays on. Do not describe a use as guaranteed to improve the word.

## Assumptions & contingencies

- **Policy numbers are tunable taste**: retain the proposed weights and use probabilities for the first implementation. Vowel-less racks prefer Vowel Magnet at about 54–66% with today's three offers. Use probabilities are per opportunity, not a promise about the fraction of whole hands that spend a power; repeated turns and the last-chance window affect that rate. Measure the resulting mix before changing the constants. Any intentional tuning must update the theoretical preference expectation and reviewed Wild fixtures together.
- **Pinned literals**: derive initial policy fixtures and the Wild browser path from deterministic runs, explain why their expected actions satisfy the rules, then freeze them. Investigate every later mismatch before changing a pin. Classic behavior is outside this gameplay change and must retain its current expectations; never re-pin a Classic regression to accommodate unintended drift. Fixed-seed determinism also assumes the same dictionary, public state and legal input time. The early four-seat draw closes after exactly three pick beats by design, not by whichever beat count a first run happens to show.
- **Timeouts remain rules, not test patience**: a late hero pick can legitimately leave too little time for all three bots to choose; the shared draw timeout supplies their defaults. Do not extend `POWER_DRAW_MS`, renew turn clocks, compress CPU beats or blindly increase waits to make a failure pass. Confirm the engine progressed and selectors identify the intended card before adjusting a browser wait for measured slowness.
- The native device flows have no Wild variant; nothing to update there. Online bots stay scripted ("keep the first offer, never use it") — out of scope by the ticket.
